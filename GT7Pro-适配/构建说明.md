# 构建说明（GT7 Pro 轻量版）

> 这一版**可以放心刷进真我 GT7 Pro**：它只装纯应用层钩子，不挂 `/odm`、不加载原生库、不碰任何相机配置文件。
> 为什么完整版在这台机器上做不出来（实测证据），见 `适配评估报告.md` 第五节。

---

## 0. 现成的产物（不用自己编）

源码已经推到 GitHub，并在 GitHub Actions 上编译好了：

| 位置 | 内容 |
|---|---|
| 仓库 | https://github.com/872446136-source/OmniCam-Muse-GT7Pro |
| 发布页 | https://github.com/872446136-source/OmniCam-Muse-GT7Pro/releases/tag/v4.0-gt7pro-lite |
| `OmniCam-Muse-GT7Pro-KSU.zip` | 刷进 KernelSU / Magisk 的模块（内含已签名的设置应用） |
| `OmniCam-Muse-Lite.apk` | 设置应用本体（手动安装 / 覆盖升级用） |

构建信息：AGP 9.4.1 / Kotlin 2.4.20 / Gradle 9.7.1 / compileSdk 37 / JDK 21，`versionCode 310`、`versionName Muse 4.0 GT7Pro`。
签名用仓库里的 `signing/port.p12`（PKCS12，别名 `omnicam`，口令 `omnicam`），证书 SHA-256 指纹
`65:8C:41:2C:7B:95:39:D7:24:A5:A0:67:E5:AD:6B:58:B4:0F:5D:EC:FE:58:21:B6:B7:AD:62:56:F0:FD:74:9A`，
所以以后再构建也能直接覆盖安装。

改完代码想重编：推到 `main` 就会自动构建（`.github/workflows/build.yml`），或者在 Actions 页面点 `Run workflow`。
云端构建会先跑 `.github/strip_native.py` 把 CMake/NDK 部分从 `app/build.gradle.kts` 里剥掉——轻量版不加载原生库，
没必要为它下一个 1 GB 的 NDK。

下面是本地自己编译的流程（没有云端构建时才需要）。

## 1. 补丁做了什么

`patch/gt7pro-lite.diff` 一共 10 个文件、114 行新增、10 行删除：

| 文件 | 改动 |
|---|---|
| `app/src/main/assets/symbols.json` | 按相机 7.006.112 修正 4 处钩子特征（详见报告 3.3） |
| `app/src/main/assets/native_init` | **删除**。LSPosed 会按这个清单自动把 `libjiege_native.so` 注入进程，原生半边会改 ODM 路径、patch 调音库，没有 payload 时会出事 |
| `app/src/main/java/local/jiege/hook/common/Profile.java` | 新增，`LITE = true` |
| `app/src/main/java/local/jiege/hook/ModuleEntry.java` | 相机 / 相册两条分支各加一个 `LITE` 早退，新增 `installLiteCamera` / `installLiteGallery` |
| `app/src/main/kotlin/local/jiege/ui/Diagnostics.kt` | 状态卡第一项从「KSU 模块挂载」改成「轻量模式」 |
| `module/lite` | 新增标记文件（内容随意，存在即轻量） |
| `module/post-fs-data.sh` | 见到 `lite` 直接退出；另加机型守卫：缺 `lighthouse*` 调音文件就不挂载 |
| `module/service.sh` | 见到 `lite` 直接退出（不再 stage POP 配置） |
| `module/customize.sh` | 刷入时删掉 `payload/` 和 `system/`（那是 X9 Ultra 的原件，几百 MB） |
| `module/module.prop` | 改名 `OmniCam Muse Lite`，版本 `Muse 4.0 GT7Pro`（模块 ID 仍是 `ricoh_pop_x9u`） |

## 2. 环境

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 17 或以上（推荐 21） | AGP 9.4.1 要求 |
| Android SDK Platform | **37** | `compileSdk = 37` |
| Android NDK | **29.0.14206865** | 版本号写死在 `app/build.gradle.kts`，装别的版本会直接报错 |
| CMake | 3.22.1 | 同上 |
| Python | 3.10+ | `build.ps1` 的离线测试要用 |
| Git for Windows | 任意 | `build.ps1` 会调用 `C:/Program Files/Git/bin/bash.exe` 做 shell 语法检查 |

`local.properties` 里写 `sdk.dir=...`（或用 `ANDROID_HOME` 环境变量）。

> NDK / CMake 在轻量版里其实用不上：`libjiege_native.so` 运行时不加载（`native_init` 已删，代码里也没有 `System.loadLibrary`）。
> 但 `app/build.gradle.kts` 里声明了 `ndkVersion` 和 `externalNativeBuild`，Gradle 配置阶段仍会去找它，所以要么装上，要么把那两处删掉。

## 3. 打补丁（唯一一步）

```bash
cd OmniCam-Muse
git apply GT7Pro-适配/patch/gt7pro-lite.diff
git status --short
```

`git status` 应看到 10 个文件（9 个 M/A/D + 1 个 `??`→`A` 的 `module/lite`）。

补丁已验证：在一份只有这 10 个文件原始版本的干净目录里 `git apply` 能一次过，不依赖本机仓库状态。

想退回上游原样：

```bash
git apply -R GT7Pro-适配/patch/gt7pro-lite.diff
```

（`Profile.LITE` 单独改回 `false` 也能恢复完整功能集，但那需要 `native_init` 和 payload 都回来，见第 6 节。）

---

## 4. 编译

```powershell
$env:OMNICAM_PYTHON = 'python'
.\build.ps1
```

`build.ps1` 会依次做：色彩目录校验 → 离线测试 → 三个 shell 脚本的语法检查 → `assembleRelease` → 签名并打包 `OmniCam-Muse-<版本>-KSU.zip`。

### 签名（必须）

根目录放 `port.keystore`，或者设 `OMNICAM_KEYSTORE` 指向它，并设置：

```powershell
$env:OMNICAM_STORE_PASSWORD = '...'
$env:OMNICAM_KEY_ALIAS      = '...'
$env:OMNICAM_KEY_PASSWORD   = '...'
```

没有 keystore 时只产出 `app-release-unsigned.apk`，**不会**生成 KSU zip（`customize.sh` 要装 APK，装不了就没法用）。

> 不同证书签名的 APK 不能互相覆盖安装。如果你手机上装过别人的 OmniCam，先卸载 `local.jiege.camera`。

## 5. 刷入与验证

1. KernelSU / Magisk 刷 `OmniCam-Muse-<版本>-KSU.zip`（模块 ID：`ricoh_pop_x9u`），重启。
   - `customize.sh` 刷入时就把设置应用装好（`local.jiege.camera`），并在 `/data/adb/modules/ricoh_pop_x9u/install.log` 留一行结果。
   - 同一步会把 `payload/`、`system/` 删掉，模块目录只剩几 MB。
2. LSPosed 里启用 OmniCam Muse，作用域勾：**系统框架、相机（`com.oplus.camera`）、相册（`com.coloros.gallery3d`）**。
   - 系统框架这一项不能漏：静音下的快门声、批量水印的后台虚拟屏都靠它。
3. 强制停止相机再打开。
4. 打开桌面「OmniCam Muse」，状态卡第一行应是绿色的**轻量模式**（原文「未挂载 /odm，只装应用层功能」），后面几项依次是 LSPosed / 相机注入 / 符号匹配 / 功能加载。

出问题：KernelSU 里停用模块并重启即可，轻量版本来就没有任何挂载，停用等于完全还原。

### 排错

| 现象 | 看哪里 |
|---|---|
| 相机没变化 | 设置应用状态卡；LSPosed 作用域是否勾了相机；`/data/adb/modules/ricoh_pop_x9u/install.log` |
| 符号匹配失败 | 设置应用主页状态卡会显示「N 个符号未匹配」（可点导出日志）；LSPosed 日志里搜 `Symbols`，会打出 `N resolved, M missing` 和每个缺失的键；电脑上先跑第 8 节那条命令最直观 |
| 相机崩溃 | `adb logcat -b crash`；HAL 崩溃看 `/data/tombstones` |
| 相机调试日志 | `setprop oplus.autotest.camera.debug.forcelog true` 再强停相机，日志在 `/data/vendor/cam_alog/` |
| 刷完没装设置应用 | `install.log` 里的 `INSTALL_FAILED_*`：多半是证书冲突，先卸载 `local.jiege.camera` 再刷 |

设备侧的坑（`su -c` 只有第一条是 root、临时 bind 挂载只卸一层等）记在上游 `docs/DEV_NOTES.md`。

## 6. 这一版有什么、没什么

### 装了（11 项，全部不依赖 `/odm`）

| 功能 | 类 | 作用 |
|---|---|---|
| 快启键模式 | `KeyLaunchMode` | 双击音量键启动到指定模式，而不是上次的模式 |
| 快门声 | `ShutterSound` + `CameraSoundForced` | 静音 / 振动模式下也出声（相机侧改判断，框架侧放开流类型） |
| 模式状态分离 | `ModeStateSplit` | 闪光灯、实况照片按模式各自记忆，切模式不互相污染 |
| 4K60 滤镜 | `VideoFilterHighSpec` | 普通录像在 4K / 60fps 下保留 `.bin` 滤镜（上游三处封锁一起解） |
| 机型伪装 | `ModelSpoof` | 大师水印机型文字 + EXIF `Model` 标签 |
| 视频水印保护 | `VideoWatermarkGuard` | 某方向没有水印位图时丢掉 bundle，避免录像被 NPE 打断 |
| 相机日志镜像 | `CameraLogMirror` | 相机日志同时写一份到模块目录 |
| 相册水印系列解锁 | `WatermarkSeriesUnlock` | 照片编辑器里哈苏 / LUMO / GR 水印对每张照片可选 |
| 批量水印 | `BatchWatermark` | 多选「更多」→ 批量编辑水印，可加也可用「无」去掉 |
| 地址跳转 | `AddressNavigation` | 照片详情里的地址点开跳地图 |
| 相册批量后台 | `BatchWatermark.installSystem` | 在系统框架侧维持虚拟屏，批量时能切走干别的 |

### 没装（完整版功能，缺 payload / 原生 patch / 系统里根本没有的模式）

| 功能 | 卡在哪 |
|---|---|
| 滤镜目录注入、X10 滤镜 | `FilterGroupInjector` / `X10FilterPort` 读模块的滤镜目录与 LUT |
| GR 移植（相机 + 相册水印） | 需要 `setting_Retro` basictone 与 GR LUT，`/odm` 里没有对应目录 |
| POP 复古相机、25MP | 需要 `libAlgoInterface` 的 `25021` 决策家族 —— 本机只有 `24019/24811/24821/24851` |
| 大师色彩、大师滤镜、LUT 槽位、对比度 | 需要 `libBasicTonePhotoX9.so` / `libCombineLut.so`，本机 `/odm/lib64` 里都没有 |
| 自然色彩、柔光 | 需要调音 json 与 `libBasicTonePhoto` 的原生 patch |
| 哈苏超清、2 亿人像 | 原生 patch + `com.oplus.feature.master.hq.raw.support = 0` |
| 移轴拍摄 | 模式在（`tiltShift`），但算法在 `libAlgoInterface` 的 `24019` 家族里，偏移要重新推 |
| 无缝模糊保护 | 依赖 POP 路径 |
| 相册调色板 | 依赖模块的色彩表 |
| XPAN | `com.oplus.feature.xpan.mode.support = 0`，`mode_data.db` 里也没有该模式 |

## 7. 想做成完整版还缺什么

1. **payload 重建**：`module/payload/*` 必须从 GT7 Pro 自己的 `/odm/etc/camera/` 生成。`采集设备信息.sh` 已经采过一份，但采集到的东西恰好证明了路走不通 —— 详见报告 5.1~5.4。
2. **原生偏移重推**：`tools/patch_25mp.py`、`patch_grain_gate.py`、`app/src/main/cpp/*.cpp` 里的地址是按 X9 Ultra 的 `25021` 家族写死的，本机没有这个家族，全部要按 `24019` 重新定位。
3. **模式定义**：新增模式（GR / POP / XPAN）要写 `camera_unit_feature_config.protobuf`，需要它的 proto schema，仓库和固件里都没有。
4. **缺库**：`libBasicTonePhotoX9.so`、`libCombineLut.so` 在 GT7 Pro 的 `/odm/lib64` 里不存在，靠改配置补不出来。
