# 512 测试版：恢复本地修复并补齐 POP 资源

日期：2026-11-16。目标：RMX5010 / 相机 7.013.51 / 相册 17.10.41。

本版以仓库 505（5aedc44）为基础，结合本地 506–511 APK、11 月 11 日调试日志和参考包恢复修复。尚未合入上游新增功能。它是供真机回归的候选版本，不能以编译通过代替实拍结论。

## 修复内容

- **POP 拍摄**：恢复 511 在 RMX5010 上使用独立普通拍照 SDK 会话的实现。相机应用仍保持 POP 模式、滤镜和边框；SDK 的正常拍摄检查保留。后端安装成功后不再叠加旧的拍摄放行钩子。
- **POP 预览调节**：恢复对 FilterIpuAdapter 已传入的暗角、清晰度、颗粒大小和颗粒数量的转发。仅限 POP 当前帧及该帧对应的处理单元，嵌套调用结束后清理上下文。它不伪造界面没有传来的参数。
- **POP 调色资源**：构建时保留 CombineLut 要读取的两份 Master 配置、18 张 SC32/CWCM32 表及 64³ BaseLut。它们与旧 BasicTonePhoto 的 SimTool.ini、SCLut 表并存；不会用 32³ 表覆盖旧引擎需要的 64³ 表。验证输入文件大小、数值和通道排列后再打包。
- **XPAN**：将相机表面声明与 HAL 实际交付尺寸对齐；按实际水印输入图像居中裁为约 65:24，坐标与尺寸按 YUV 偶数对齐。恢复 511 中原先需要调试开关才能启用的 XPAN 水印处理模式，使有效的裁切坐标能被 SDK 使用。未知布局不安装该修复。
- **哈苏水印**：从本机已安装相册读取匹配样式与缺失图片。设置键延后到实际请求时读取，避免 506 启动等待；不复用另一个哈苏样式的缓存，不干预 POP、GR 或视频。
- **快门声与符号**：恢复 511 的两个符号变更，以及 7.013.51 合并后的静音／恢复消息处理适配。

没有替换 GT7 Pro 的 libAlgoInterface、BasicTone 库或 HAL 配置。数据层基于已发布的 505 完整包；新增调色表已与本地旧实验及参考资源核对。原有 Meishe 渲染库保持不变。

## 真机验证步骤

1. 在 KernelSU 刷入完整的 `OmniCam-Muse-GT7Pro-512-test-KSU.zip`，重启。
2. 打开模块设置确认显示 512；LSPosed 作用域包含系统框架、相机和相册。
3. 打开 POP，在固定场景下分别将各调节拉到最低和最高，比较预览与保存照片；切换各款滤镜后连续拍摄，并分别测试实况开／关。
4. XPAN 横拍、竖拍各拍两张，确认保存成功、画面方向正确；无边框成片的长短边比例应约为 2.708。核对相册中显示的尺寸及画面与取景框是否一致。
5. 从相机进入哈苏水印页面，切换不同样式拍照，确认缩略图、标志和文字正常，并检查普通拍照、GR 和视频。
6. 若仍异常，记下模式、滤镜、调节值、实况状态和复现操作，通过模块导出日志，并保留对应原图。

需要特别确认：光感／自然饱和度等参数在本机是否真正从界面传出、色温／色调对成片是否生效，以及 POP 实况和 XPAN 实况的完整保存流程。这些必须由真机结果判定。
