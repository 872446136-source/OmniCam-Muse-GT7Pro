# OmniCam Muse → 真我 GT7 Pro 适配报告（最终版）

目标设备：**realme RMX5010（真我 GT7 Pro）**，`RMX5010_17.0.0.111(CN01)`，Android 17 / SDK 37
相机 `com.oplus.camera` 7.006.112，相册 `com.coloros.gallery3d` 17.10.37
上游：OmniCam-Muse（原适配 OPPO Find X9 Ultra，PMA110，相机 7.006.119）

---

## 一、结论

| 项 | 结果 |
|---|---|
| 钩子层（LSPosed 符号定位） | ✅ 相机 **255/255**，相册 29/31 |
| 完整功能集（GR / POP / 大师色彩 / 调色盘 / 25MP / 200MP / 柔光 / 颗粒…） | ❌ **不能移植**，不是改配置能解决的 |
| 纯应用层功能 | ✅ **已做成"轻量版"构建**，见第五节 |

**为什么完整版不行**：拿到设备数据后确认，GT7 Pro 和 Find X9 Ultra 的相机**不是同一个配置世代**——决策配置格式不同、原生管线类族不同、大师色彩链路整体关闭、GR/POP 模式根本不存在。详见第三节，每条都有文件证据。

## 三、完整版为什么不能移植（四条硬证据）

### 1. 决策配置不是同一代

你的 `oplus_camera_preview_decision_config.json`（解密后）只有 **34 个 multiAlgo 节点**：

```
ALGO_VIDEO, ALGO_TURBO_HDR_*, ALGO_QUADCFA, ALGO_MFNR, ALGO_HYBRIDRAW, ALGO_MASTER_SINGLE_RAW ...
```

- **没有** 25M 高像素节点（`ALGO_HR_REAR_W1X-2X_25M_DCG_3EXP` 等），`tools/patch_25mp.py` 找不到目标会直接报错；
- **没有** `paramsHolder->retro_camera_mode`，POP 的 BasicTone 分支无处可加。

X9 Ultra 的那份里有 25M 节点和全套 `SINGLE_ALGO_*`。**两代决策格式不同。**

### 2. 原生管线类族不同 → 所有字节补丁偏移失效

模块在 `libAlgoInterface.so` 里按固定地址打 NOP/跳板（`0x24B0DA0`、`0x1AD2A4`、`0x2902EA0`…），目标函数是：

```
ApsCapDecisionRearNormal25021::addCommonPipelines
ApsCapDecisionFrontNormal25021::addCommonPipelines
```

你的库里实际是：

```
ApsCapDecisionRearNormal24019::addCommonPipelines    @0x0204c4a0
ApsCapDecisionFrontNormal24019::addCommonPipelines   @0x02058cb8
ApsCapDecisionRearNight24019 / FrontNight24019 / RearBokeh24019 / FrontBokeh24019 ...
```

**没有 25021 这个族**，全是 `24019`（另有 `24811/24821/24851` 的视频族）。地址套过去不是"不生效"，是把随机指令改成 NOP —— 相机 HAL 会直接崩。

### 3. 大师色彩 / 调色盘的两个依赖库不存在

`/odm/lib64` 实际只有：

```
libAlgoInterface.so   60 MB
libBasicTonePhoto.so  513 KB     ← 有 BasicTone::MergeLutTet、BasicTone_OGL::load3DLut<half>
libmsnativefilter.so  7.2 MB     ← 有 MsRenderHDRTexture、ProMist
```

**没有** `libBasicTonePhotoX9.so`，**没有** `libCombineLut.so`。而模块的"大师 LUT 槽 / 对比度 / 颗粒"挂在 `MergeLutTet_resize`（X9 专有）和 `MergeLutTet_resize2rgb` 上 —— 这两个符号在你的库里都不存在。

### 4. 相机特性开关：哈苏色彩整体关闭，GR/POP 不存在

从解密后的 `oplus_camera_config` 读出：

| 开关 | 值 | 含义 |
|---|---|---|
| `com.oplus.use.hasselblad.style.support` | **0** | 没有哈苏色彩 → 大师色彩无从谈起 |
| `com.oplus.feature.master.hq.raw.support` | 0 | 无 HQ RAW |
| `com.oplus.feature.tilt.shift.photo.support` | **1** | 移轴**已经开着**（不需要移植） |
| `com.oplus.feature.xpan.mode.support` | 0 | XPAN 关闭 |
| `com.oplus.ocs.camera.ipu.meishe.filter.support` | 1 | 普通滤镜/LUT 支持 |

`mode_data.db` 里的模式（19 个）：

```
night, street, commonVideo, common, portrait, more, professional, highDefinition,
panorama, masterVideo, slowVideo, fastVideo, longExposure, multiCamera,
underWater, idPhoto, docScan, starry, tiltShift
```

**没有** `gr`、`retroCamera`、`xpan`。而 GR / POP / XPAN 正是模块的三个主打功能。

## 四、所以能做什么

| 依赖 | 功能 | GT7 Pro |
|---|---|---|
| 只用相机/相册自己的类 | 快门声、快启键、机型伪装、水印解锁、批量水印、地址跳转、4K60 滤镜、按模式记忆 | ✅ **可用** |
| 需要设备自己的配置重新生成 | 移轴（已开）、25MP（无此节点）、XPAN（关） | ⚠️ 无意义 / 需另做 |
| 需要 X9 Ultra 的原生库或模式 | GR、POP、X10、调色盘、大师色彩、大师滤镜、柔光、颗粒、对比度、LUT 槽 | ❌ 不可用 |

移轴是个有意思的点：**你的机器本来就支持移轴**（`tiltShift` 在模式列表里，`SINGLE_ALGO_TILT_SHIFT` 在决策配置里），模块在这台机上是多余的。

## 五、交付：轻量版（Muse Lite）

已经改好代码，见 `patch/gt7pro-lite.diff`。

### 装什么

| 功能 | 说明 |
|---|---|
| 快门声 | 静音/振动模式照常出声，可单独设音量（相机 + system_server 两侧） |
| 快启键指定模式 | 快启键直接进指定模式，不跟随上次模式 |
| 机型伪装 | 大师水印机型文字 + 成片 EXIF Model 可替换 |
| 水印系列解锁 | 相册编辑器里哈苏 / LUMO / 理光水印对所有照片开放 |
| 批量编辑水印 | 多选 → 更多 → 批量加水印 / 选"无"批量去除 |
| 地址跳转 | 照片详情点地址开地图 |
| 4K/60fps 保留滤镜 | 普通视频不再掉到 1080p30 |
| 按模式记忆 | 闪光灯、实况开关各模式分别记住 |
| 日志与诊断 | 设置应用的状态卡、日志导出 |

### 怎么改的（9 个文件 + 1 个标记，全在 `patch/gt7pro-lite.diff` 里）

| 文件 | 改动 |
|---|---|
| `app/.../assets/symbols.json` | 按 7.006.112 修正 4 处钩子特征（见 2.3） |
| `app/.../assets/native_init` | **删除**。LSPosed 会按这个清单自动把 `libjiege_native.so` 注入进程，而原生半边会重定向 ODM 路径、patch 调音库——没有 payload 时必须让它别加载 |
| `app/.../common/Profile.java` | **新增**。`Profile.LITE = true` —— 声明这是"无 payload"构建 |
| `ModuleEntry.java` | LITE 时只装上面那批钩子，**不调用 `System.loadLibrary`**，不走 `/odm` 挂载判断 |
| `ui/Diagnostics.kt` | 状态卡在 LITE 下显示"轻量模式：未挂载 /odm"，不再报"相机库未挂载"的假警报 |
| `module/post-fs-data.sh` | 有 `module/lite` 就一个文件都不挂；**另加机型守卫**：本机没有 `lighthouse*` 调校文件就不挂（防止拿完整版 payload 刷到 GT7 Pro 上） |
| `module/service.sh` | 有 `module/lite` 就直接退出，不写 GR/POP/移轴的开关、不重建模式库 |
| `module/customize.sh` | 刷入时删掉 `payload/` 和 `system/`，省 300+ MB，也免得被误挂 |
| `module/lite` | **新增**标记文件（内容 `1`，存在即轻量） |
| `module/module.prop` | 改名 `OmniCam Muse Lite` / `Muse 4.0 GT7Pro`，versionCode 310 |

`Profile.LITE` 和 `module/lite` 必须一致：前者决定装哪些钩子，后者决定挂不挂文件。

补丁已在一份"只有原始文件"的干净目录里验证过 `git apply` 一次过。

## 六、已知缺口

### 6.1 相册那 2 个符号

`Section.segmentSetup` / `Section.cameraStyles` —— GR 水印在相册编辑器里的"相机风格 chip 组"。17.10.37 里那串 Kotlin 空检提示已不存在，同类里符合特征的候选有 3 个 `()Z` + 2 个 `()V`，**静态分不清**。改错会破坏水印编辑页布局。

影响：相册状态卡会显示"2 个符号未匹配"。功能上只少了 GR 水印的 chip 组，**不影响出图和其他水印**。

### 6.2 状态卡

LITE 下 `KSU 模块` 那一行换成了"轻量模式"，这是有意的 —— 模块确实没挂任何文件。

### 6.3 如果还想要 GR / POP

那等于重新做一个项目：

1. 在 `camera_unit_config` 加 `gr_mode` / `retro_camera_case`，在 `camera_unit_feature_config.protobuf` 加特性 —— **需要 proto schema，仓库没带**；
2. 模式库重建、GR 的 LMT/LUT 资源按你的 sensor 重新标定；
3. `libAlgoInterface.so` 按**你的库**重新反汇编定位对应函数（`24019` 族），重写全部补丁。

第 3 步我可以做（库在手上，反汇编思路清楚），但前两步缺 schema，而且这套东西没有真机反复试错调不出来。
